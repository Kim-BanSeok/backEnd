# 담당표

API 번호와 이름은 `Material_Loop_API_명세서_v0.3.docx` 의 4장 "API 목록" 기준입니다.
**같은 파일을 둘이 동시에 고치지 않도록** 담당이 아닌 API 는 건드리지 않습니다. 담당을 바꾸려면 먼저 말하고 이 표를 같이 고칩니다.

- **리더**: 공통 기반, 위험한 로직(재고·동시성·AI), 모든 PR 의 최종 리뷰와 머지
- **서브**: 작고 독립적인 기능. 기존 회원 API(`auth`, `users`)를 보고 따라 하는 일부터

상태: `완료` / `진행` / `대기`

## 공통 메모

- **원단 파일 이름 (충돌 방지)**: 리더가 만든 원단 등록·수정·삭제는 `fabrics.*` 파일(`routes/fabrics.routes.js`, `services/fabrics.service.js`, `dao/fabrics.dao.js`, `validators/fabrics.schema.js`, `tests/fabrics.test.js`)입니다. 서브의 원단 조회(10·11·14번)는 **`fabricsRead.*`** 로 새 파일을 만들고(`fabricsRead.routes.js`, `fabricsRead.service.js` 등, 테스트는 `tests/fabrics-read.test.js`), `fabrics.*` 파일은 고치지 않습니다. `routes/index.js` 에는 한 줄만 추가합니다.
- **원단 의존**: 관심저장(원단 대상)과 문의는 원단이 있어야 의미가 있습니다. 원단 등록 API 가 나오기 전에는 `tests/helpers.js` 의 `makeStore`, `makeFabric` 으로 테스트용 원단을 만드세요.
- **도안 데이터**: 도안(`patterns`, `pattern_parts`) 시드 데이터와 추천 판정 규칙(기획서 v11 4.2·4.3)은 리더가 정합니다. 서브는 테스트에서 직접 도안을 만들어 쓰세요.
- **DB 변경이 필요하면**: 서브는 `models/`, `migrations/` 를 고치지 않고 리더에게 요청합니다.
- **명세서가 바뀌면**: 명세서(docx)가 기준이고, `docs/API_명세서_v0.3.md` 는 읽기 편하게 변환한 사본입니다. 둘이 다르면 docx 를 따릅니다.
