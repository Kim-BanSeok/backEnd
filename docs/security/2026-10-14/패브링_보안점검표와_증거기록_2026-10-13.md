# 패브링 보안 점검표와 증거 기록

> 저장소 보관본: 아래 내용은 점검 당시의 기록이다. 이후 사용자 요청으로 보안 브랜치에 커밋·푸시하며, 로컬 경로·시험용 서명값은 공개용으로 정리했다. 원본 증거와 ZIP은 로컬에 보존한다.


기준 확인일: 2026년 10월 13일

2026년 10월 14일 갱신: [P0 개선과 재점검](패브링_P0_보안개선과_재점검_2026-10-14.md)에 비밀번호·로그아웃·사진·AI 제한 및 본문 타임아웃의 개선 결과를 연결했다. 아래 작업 묶음에는 남은 적용 범위도 함께 표시한다.

이 점검표는 [보안 기준 선정과 적용 계획](패브링_보안기준_선정과_적용계획_2026-10-13.md)의 16개 작업에 2026년 10월 13일의 실제 점검 결과를 반영했다. [점검 결과와 개선 우선순위](패브링_보안점검결과와_개선우선순위_2026-10-13.md)에 재현 조건과 코드 근거가 있다. 통과한 시나리오가 있어도 묶음 안에 미확인 범위가 남으면 점검 중으로 기록한다.

기준 판본은 ASVS 5.0.0, API Security Top 10 2023, WSTG 4.2, KISA JavaScript 시큐어코딩 가이드 2023년 개정본이다. 발표 위험 분류는 OWASP Top 10 2025, AI 추가 분류는 LLM Top 10 2025를 사용한다. KISA 문서는 주제별로 연결한 뒤 원문 절과 페이지를 결과에 기록한다.

## 상태와 완료 판정

| 상태 | 의미 |
| --- | --- |
| 미점검 | 요청·응답·저장 결과를 확인하지 않음 |
| 점검 중 | 일부 시나리오만 확인함 |
| 통과 | 확정한 해당 요구사항의 허용·거절 시나리오와 증거가 모두 충족됨 |
| 개선 필요 | 재현된 문제 또는 충족하지 못한 요구사항이 있음 |
| 개선 후 통과 | 변경 후 동일 시나리오와 정상 흐름의 재점검을 통과함 |
| 보류 | 배포 구성이나 정책 결정 등 구체적인 의존 사항이 남음 |
| 적용 제외 | 기능이나 환경에 해당하지 않으며 제외 사유가 기록됨 |

P0는 공개 전, P1은 거래·AI 운영 전 우선 작업이다. 운영 로그의 탐지·알림 정책과 SBOM 보강 등 확장 항목은 팀 일정에 맞춰 P2로 관리할 수 있다. 개별 취약점의 심각도는 영향과 재현 조건을 근거로 별도 기록한다.

## 첫 점검 시나리오

테스트 대상은 격리 DB와 가상 데이터를 사용하는 로컬 또는 준비된 테스트 서버다. 구매자 A와 B, 판매자 A와 B, 미승인 판매자와 관리자를 준비한다. API 기준 경로는 `/api/v1`이며 아래 경로는 그 뒤의 상대 경로다.

### 타인 예약과 관리자 기능

구매자 A가 소유한 예약 ID를 준비하고 구매자 B의 토큰으로 `GET /reservations/{id}`와 `POST /reservations/{id}/cancel`을 요청한다. 정상 소유자의 허용 요청도 같이 확인한다. 정책에 따른 403 또는 404 응답과 정보 노출 여부, 예약과 재고의 변화 여부를 기록한다. 거절 응답만으로 완료 판정하지 않는다.

같은 절차를 다른 판매자의 원단·사진·문의와 AI 세션으로 확장한다. 구매자와 일반 판매자가 관리자 API를 직접 호출했을 때도 기능과 데이터 변경을 거절해야 한다.

기준: `v5.0.0-8.2.1`, `v5.0.0-8.2.2`, `v5.0.0-8.3.1`, API1·API5:2023. 검증 절차: [WSTG 4.2 WSTG-ATHZ-04](https://wstg.owasp.org/v4.2/4-Web_Application_Security_Testing/05-Authorization_Testing/04-Testing_for_Insecure_Direct_Object_References/).

### 로그아웃 이후 세션

테스트 계정으로 로그인하고 토큰을 안전한 테스트 메모리에 보관한다. 프론트에서 로그아웃한 뒤 그 토큰으로 `GET /users/me`를 다시 요청한다. 클라이언트 저장소 제거와 서버의 토큰 종료를 각각 기록한다. 재사용이 허용된다면 현재 설계와 ASVS 요구사항의 차이를 개선 대상으로 기록하고, 서버 종료 계약을 추가한 뒤 동일 테스트를 반복한다.

기준: `v5.0.0-7.4.1`. 검증 절차: [WSTG 4.2 WSTG-SESS-06](https://wstg.owasp.org/v4.2/4-Web_Application_Security_Testing/06-Session_Management_Testing/06-Testing_for_Logout_Functionality/).

### 다국어 비밀번호 경계

72바이트 이하와 초과인 ASCII·한글·이모지 비밀번호를 준비한다. 서로 다른 두 비밀번호가 bcrypt 처리에서 같은 앞부분으로 잘리지 않는지 확인한다. 입력 거절 또는 해시 알고리즘 변경 정책을 정하고 가입과 로그인의 처리가 일치하는지 검증한다. 사용자 비밀번호 원문을 결과 로그에 남기지 않는다.

기준: `v5.0.0-6.2.8`, [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).

### 사진 업로드 경계

정상 JPEG·PNG·WebP, 이미지처럼 이름 붙인 비이미지 파일, 손상 이미지, 5 MiB 경계와 초과 파일, 허용 픽셀 경계와 초과 이미지를 준비한다. 자신의 원단과 타인의 원단에 각각 업로드한다. 응답, DB 행, 원본과 썸네일 파일을 확인한다. 업로드 전에 판매자 인증을 거절하는 경우와 업로드 후 소유권을 거절하는 경우의 자원 사용도 비교한다.

정상 원본에서 위치정보 등 EXIF가 공개되는지 확인하고 공개 정책을 기록한다. 현재 허용 픽셀 값은 검토 코드의 `40_000_000`을 출발점으로 삼되, 운영 처리 능력에 맞춰 결정한다.

기준: `v5.0.0-5.2.1`, `v5.0.0-5.2.2`, `v5.0.0-5.2.6`, `v5.0.0-5.3.2`. 메타데이터 제거를 선택하면 `v5.0.0-14.2.8`도 연결한다.

### 마지막 재고와 중복 처리

가용 재고가 한 예약만 수락할 수 있는 원단을 준비한다. 수락 요청을 동시에 실행하고 DB의 예약 상태와 재고 합계를 비교한다. 같은 요청의 재전송, 수락과 취소의 경합, 수령과 취소의 경합도 확인한다. 금지된 상태 순서를 건너뛰어 수령 처리할 수 없는지 검증한다.

기준: `v5.0.0-2.3.1`, `v5.0.0-2.3.3`, `v5.0.0-2.3.4`, API6:2023.

### AI 비용과 출력

가짜 AI 제공자로 허용 필드 밖의 값, 잘못된 형식, 지시문을 포함한 판매자 입력, 실패와 지연 응답을 검증한다. 권한이나 승인 상태를 AI 출력으로 바꿀 수 없어야 한다. 초안은 정한 서버 검증과 판매자 확인을 거쳐 저장돼야 한다.

사용자별 한도·전체 한도·동시 처리·재시도 정책을 먼저 기록하고, 한도를 초과하는 요청이 실제 외부 모델 호출 전에 중단되는지 호출 수로 확인한다. 실제 모델을 통한 프롬프트 인젝션 검증은 가짜 제공자 테스트와 별도 결과로 남긴다.

기준: `v5.0.0-2.4.1`, `v5.0.0-15.2.2`, API4:2023, [LLM01·LLM05·LLM06·LLM10:2025](https://genai.owasp.org/llm-top-10/).
