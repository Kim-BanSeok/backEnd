# 패브링 Strix 실행과 보안 개선 전후 검증

> 저장소 보관본: 아래 내용은 점검 당시의 기록이다. 이후 사용자 요청으로 보안 브랜치에 커밋·푸시하며, 로컬 경로·시험용 서명값은 공개용으로 정리했다. 원본 증거와 ZIP은 로컬에 보존한다.


검증일: 2026년 10월 14일

비밀번호 처리, 로그아웃 토큰 폐기, 사진 접근 권한, AI 호출 제한의 **네 P0 영역을 다섯 시나리오로 직접 재현**했다. 개선 전에는 문제가 재현됐고, 개선 후에는 공격을 차단하면서 정상 로그인과 소유자의 사진 접근이 유지됐다. 원본 프론트·백엔드 파일 488개의 해시와 두 Git HEAD가 시험 시작 시점과 같으며, 새 커밋이나 스테이징은 하지 않았다.

**Strix 자동 모의해킹의 개선 전후 비교는 완료되지 않았다.** 개선 전 소스 검토 이후 OpenAI 구독 모델의 보안 관련 가드레일이 실행을 중단했다. Strix의 실패 기록과 직접 재현 결과를 분리했다. 아래 개선 수치는 Strix가 검증한 발견 건수가 아니라 실제 시험 사이트와 프론트 adapter를 대상으로 실행한 독립 재현 결과다.

## 개선 전 코드를 어떻게 보존했는가

보안 수정 직전에 전체 작업 폴더를 별도 백업해 둔 것은 아니다. 당시 Git 기준 커밋과 점검 증거가 남아 있었고, 이번 시험을 준비하면서 그 커밋의 추적 파일을 ZIP으로 보관하고 별도 폴더에 복원했다. 현재 미커밋 수정본도 별도 복사본과 파일 해시로 보존했다.

이는 **기준 커밋 복원본과 현재 작업 복사본**의 비교다. 수정 직전 작업 폴더의 완전한 시점 복제라고 표현하면 안 된다. 두 버전 사이의 모든 기능 차이를 P0 수정의 효과로 간주하지 않고, 동일한 보안 시나리오의 요청·응답을 비교했다. ZIP은 코드 백업이며 운영 DB·사진·환경변수 백업은 포함하지 않는다.

[개선 전 요청·응답 JSON](strix-comparison-2026-10-14/before/independent-evidence.json), [개선 후 요청·응답 JSON](strix-comparison-2026-10-14/after/independent-evidence.json), [재현 코드](reproduction/strix-comparison-2026-10-14-independent-probe.mjs.txt).

비밀번호·JWT는 기록에서 가렸다. 모든 계정과 사진은 시험용이다. 개선 전 사진 반환 URL에는 서명이 없으며, 개선 후 반환 URL은 제한된 읽기 권한을 갖는 서명 URL이다. 원시 JSON의 `validCapability`는 API가 반환한 사진 URL의 접근 결과로, 개선 전에 서명 기능이 있었다는 의미는 아니다.

사진 AI 제공자는 응답을 600ms 지연하는 동일한 가짜 제공자다. 24건 시험은 동시 입장 제한의 확인이며 처리 속도·실제 비용 절감률의 측정이 아니다. **서비스의 유료 AI API 호출은 0건**이고, **Strix 분석 모델은 실제 ChatGPT 구독 사용량을 소비**했다.

## 격리와 재현 범위

개선 전·후 각각 별도의 내부 Docker 네트워크, PostgreSQL 시험 DB, 업로드 볼륨을 사용했다. 에이전트에는 소스 복사본만 연결했다. 원본 .env·운영 계정·실제 개인정보·Docker 소켓은 연결하지 않았다. Strix telemetry와 SDK tracing을 껐다.

시험 컨테이너에서 외부 HTTPS와 호스트 게이트웨이의 새 연결이 실패하는 것을 확인했다. 두 전용 서브넷에만 적용한 방화벽 규칙은 시험 종료 시 제거했다. 작업 컨테이너는 cap_drop ALL·no-new-privileges와 CPU·메모리·PID 제한을 적용했다. OpenAI 모델 통신은 시험 컨테이너 밖의 Strix 프로세스에서 수행했다.

시험용 프록시는 127.0.0.1:45110·45111에만 열었다. 서비스 AI는 가짜 제공자로 대체했으므로 실제 외부 제공자의 응답 품질·프롬프트 공격·운영 TLS·CDN·클라우드 권한을 평가하지 않았다. 시험 컨테이너와 네트워크는 종료·제거하고, 코드 복사본·증거·가상 DB/업로드 볼륨은 재현을 위해 보존했다. 기존 다른 프로젝트의 Docker 구성은 변경하지 않았다.

## 시각 자료와 발표 문구

[발표용 PNG](strix-comparison-2026-10-14/security-before-after.png)는 네 P0 영역의 숫자 변화를 한 장으로 보여준다. [증거 대시보드 HTML](strix-comparison-2026-10-14/evidence-dashboard.html)은 항목별 개선 전후 JSON과 가려진 요청·응답을 선택해 확인할 수 있다. 정리한 수치를 보여주는 화면이며 실제 사이트 화면을 가장한 것은 아니다.

> ASVS와 KISA의 인증·인가·자원 보호 주제를 기준으로 격리된 로컬 사이트를 검증했습니다. AI 보안 에이전트 Strix로 소스와 위협 경계를 검토했지만 모델 가드레일로 자동 점검이 중단됐습니다. 보안 개선 효과는 실제 API와 프론트 로그아웃 동작을 직접 재현해 확인했습니다. 비밀번호 치환, 로그아웃 토큰 재사용, 비공개 사진 접근을 차단했고, 같은 24건의 사진 AI 요청에서 제공자 호출이 24회에서 2회로 제한됐습니다.

“Strix가 모든 취약점을 발견했고 개선 후 0건이었다” 또는 “AI가 전체 사이트의 안전성을 인증했다”는 설명은 현재 증거와 맞지 않는다.
